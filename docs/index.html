No kernel beats the vanilla table in ares. On average every one is 0.6–1.1% slower per frame. Code layout alone moves each result by ±3%, more than the gap, so any single build can show a kernel winning or losing. Each call costs ~60–70 cycles more than a table lookup. The calls win some of that back through fewer I-cache misses, because a call site is less code than an inline lookup, but not reliably.

S5C6 against Silas: S5C6 is ~10% cheaper per call at every layout, 13× more accurate, and has no dead zone (Silas returns sine 0 at angles 1–2). Per frame the two are indistinguishable. Constants loaded from a line or built in code: no measurable difference.

Use S5C6 for accuracy (100× better than the table at in-between angles), not speed. In ares it costs about the same frame time as the table; that is the whole speed claim. On a console, cache misses may cost more than ares's flat 40/48 cycles. The call builds miss less, so dearer misses would favour them. That is untested.

Vanilla is the unmodified table and plays a slightly different game (different values). Each kernel was also paired with its own table build, which plays an identical game: same conclusion, within layout noise. Fold: Silas Lock. Written with AI assistance (Claude). No ROMs distributed.
